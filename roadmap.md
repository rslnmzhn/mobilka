## Urgent — Android storage blocker
- [ ] 30. Автоматизированное исправление SAF готово и проверено: сохранённый нормализованный root-document URI теперь сопоставляется с persisted tree grant по строгой canonical identity (scheme + authority + decoded tree document ID), при этом исходный operational URI и namespace recovery journal не изменяются; child/different authority/tree, malformed URI, read-only/write-only/revoked grants покрыты регрессионными тестами. Осталась обязательная проверка на реальном Android-устройстве после перезапуска и повторного выбора той же папки: `list_skills`, `read_skill`, `write_skill`, `read_session_notes`, `write_session_notes` и создание session artifact. До этой проверки пункт не считается завершённым. Не добавлять `MANAGE_EXTERNAL_STORAGE`; при provider-specific сбое отдельно предложить совместимый provider/app-private storage или явно одобренное архитектурное решение.
- [x] 31. Добавлена отдельная локализованная кнопка копирования полного исходного `message.content` для каждого непустого сообщения пользователя и ассистента: без reasoning, metadata, статусов, tool cards, вложений и соседних сообщений; только явная запись clipboard, Material tooltip/semantics/keyboard access, RU/EN success/failure feedback и проверки на 320 px.
- [ ] 32. После отдельного явного сигнала владельца полностью переписать `README.md` как красивую проектную витрину mobilka, а не сплошной технический текст: ясный hero-блок и ценностное предложение, ключевые возможности, архитектура и безопасность простым языком, поддерживаемые платформы, установка/первый запуск, галерея интерфейса, roadmap/status и ссылки для разработчиков. Сохранить фирменный стиль mobilka без декоративных градиентов и чужого брендинга; подготовить структуру к RU/EN без дублирования устаревающих фактов. До сигнала README не изменять. Для обновления запросить у владельца актуальные скриншоты без API-ключей, личных данных и чувствительного содержимого: мобильный чат в dark и light theme; desktop adaptive shell; выбор модели; экран Agents/персон; управление Markdown memory; tool-call cards; session artifacts/предпросмотр документа; настройки endpoint с замазанными секретами; updater — только если его UX готов. Желательно PNG/WebP одного масштаба, без системных уведомлений и лишней обрезки; перед публикацией согласовать финальный набор и подписи.

- [x] 13. Реализован и автоматизированно проверен `read_public_source`: direct HTTPS transport с DNS/IP pinning, ручными redirects, cancellation, безопасными MIME/charset, лимитом 1 МиБ на вызов и UTF-8 chunks ≤256 КиБ. Persisted Conversation хранит fail-closed совокупный wire budget 8 МиБ; cache miss консервативно резервирует allowance до открытия transport, unused bytes возвращаются при штатном завершении, crash оставляет reservation списанным, cache hit бесплатен, некорректный persisted counter считается исчерпанным. Canonical URL ограничен 8 КиБ, alias metadata — 8/resource и 64/conversation. Единый RequestToolSecurityState помечает только текущий request как untrusted; mutating/sensitive/unknown и instant memory.md требуют persisted exact-call confirmation. Решение терминально завершает request; orphan executing восстанавливается как indeterminate без повторного исполнения. PromptGuard остаётся эвристикой. Focused, analyze и полный suite (556 тестов) пройдены без live internet.

## Milestone M6 — Discovery & mobile tools
- [ ] 21. Перенести персоны из монолитного `personas.yaml` в отдельные человекочитаемые файлы `personas/<slug>.md`: frontmatter хранит ID, название, краткое описание и параметры, тело — системный промпт. `list_personas` возвращает только компактный каталог метаданных, а содержимое загружается по имени только для выбранной персоны. Добавить идемпотентную миграцию с резервной копией, проверкой коллизий, безопасными confirm-flow мутациями и восстановлением; не создавать второй изменяемый индекс как конкурирующий источник истины.
- [ ] 22. Добавить интернет-поиск как отдельный инструмент `web_search`, дополняющий, но не дублирующий HTTPS-чтение из пункта 13: поиск возвращает компактные заголовки, URL и snippets, после чего агент явно выбирает страницы для безопасного чтения. До реализации выбрать один из вариантов провайдера:
  - BYOK Search API через общий адаптер (например, Brave Search, Tavily, Serper или совместимый сервис) — предсказуемый JSON, но внешний ключ, стоимость и политика приватности;
  - собственный SearXNG — больше контроля и несколько источников, но пользователь обслуживает сервер;
  - нативный web-search выбранного AI-провайдера — простая интеграция, но vendor lock-in и неодинаковое поведение моделей;
  - прямой разбор HTML поисковиков — только как нежелательный fallback из-за нестабильности и условий использования.
  Независимо от варианта: отключаемая функция, явный индикатор сетевого запроса, локаль/период/число результатов, лимиты и тайм-ауты, отсутствие секретов, данных диалога и устройства в запросах и логах, документированная privacy/retention policy провайдера, дедупликация URL и обработка запросов/snippets/страниц как недоверенного ввода через `PromptGuard`. Для SSRF-защиты применять canonical URL parsing, разрешать только HTTP(S), проверять все IPv4/IPv6-адреса DNS-ответа, отклонять loopback/private/link-local/reserved/metadata destinations, защищаться от DNS rebinding с привязкой соединения к проверенному адресу и повторять полную проверку каждого redirect.
- [ ] 23. Android-терминал, Termux, Shizuku, root и произвольную shell не реализовывать. Модель получает только workspace, созданный и неизменно привязанный к текущей сессии, и работает внутри него через типизированные инструменты из пункта 24. Доступ за пределы session workspace, shell parser, запуск произвольных процессов и privilege escalation не предоставлять. Вернуться к идее терминала можно только как к отдельному будущему архитектурному решению после нового явного одобрения владельца.
- [ ] 24. Добавить типизированные SAF-first инструменты для workspace, созданного текущей сессией: `list_files`, `search_files`, `read_file`, `write_file`, `apply_patch`, `move_file`, `delete_file`, `make_directory`. Инструменты не принимают произвольный корневой путь и всегда используют immutable workspace binding исходного запроса; мутации выполняются только внутри `sessions/<session>/`, без `MANAGE_EXTERNAL_STORAGE`, с точным preview/diff и подтверждением каждой мутации. Непосредственно перед записью повторно проверять binding, SAF scope и target, лимиты и квоты, защищаться от traversal/symlink escape и TOCTOU, использовать atomic write/recovery journal и безопасно отказываться от операции, если SAF-провайдер не позволяет подтвердить результат.
- [ ] 25. Добавить инструменты извлечения содержимого документов: PDF, DOCX, таблицы и изображения/OCR; обрабатывать локально, когда возможно, требовать отдельное явное подтверждение отправки каждого документа удалённой модели, ограничивать размер/число страниц/распаковку/ресурсы и сохранять provenance до исходного файла. Парсеры не должны исполнять макросы и скрипты, разрешать внешние сущности/ресурсы или выполнять скрытые сетевые запросы.
- [ ] 26. Отложено без реализации и не входит в текущий scope: управляемые Android intents для карт, календаря, напоминаний, share-sheet, dialer и email. Вернуться к проектированию только по отдельному запросу владельца, когда будет понятен ожидаемый UX.
- [ ] 27. Возможная будущая функция, не проектировать и не реализовывать без предварительного полного явного одобрения владельца: фоновые и периодические задачи агента, WorkManager/foreground service и уведомления о результате. Даже после одобрения потребуется отдельный security/UX design; текущие инструменты работают только в активной пользовательской сессии и не получают фоновых полномочий.
- [ ] 28. Добавить безопасный HTTP/API-клиент для пользовательских интеграций: presets с exact canonical-host allowlist, разрешёнными методами и схемой авторизации; секреты только в secure storage; preview запроса с редактированием чувствительных заголовков; лимиты тела/ответа; управляемая политика proxy. Проверять все адреса DNS-ответа, защищаться от DNS rebinding, отклонять локальные/private/link-local/reserved/metadata destinations, полностью проверять каждый redirect, ограничивать смену origin и безусловно удалять authorization при любой смене origin. Произвольный unrestricted HTTP выключен по умолчанию.
- [ ] 29. Реализовать простой и понятный UX прикрепления документов и фотографий к сообщению: одна заметная кнопка вложений, системные file/photo pickers, multi-select, preview до отправки, удаление отдельных вложений, отображение имени/типа/размера и понятные ошибки лимитов. Выбранные файлы копировать во временное app-private staging с provenance, привязывать к immutable request/conversation IDs, очищать по завершении жизненного цикла и явно показывать, какие вложения будут отправлены удалённой модели. Поддержать Android SAF и desktop `file_selector`, безопасные MIME/размер/количество, downscale/compress изображений против OOM и обработку документов через пункт 25. Буфер обмена не читать; не запрашивать broad storage или постоянный доступ ко всей медиатеке.
